## 根因

1. 所有可精确重放的牌桌标题都包含 `0.20/0.50/1`，表示三个强制盲注。旧的标题文字识别范围过大，细小标题被背景淹没，程序退回普通双盲桌，继而把第三盲注当成主动开池并错排翻前顺序。
2. 三个红色操作按钮都存在时，光学字符识别（OCR）偶尔漏掉中间“跟注”。旧逻辑只会补回漏掉的“弃牌”，导致操作集合不完整。
3. “跟注”和 `138BB` 可能被 OCR 分成两个文字框。旧逻辑只在三按钮面板内合并文字和金额，两按钮的“弃牌/跟注”面板因此丢失跟注额。
4. 小盲、大盲或第三盲注座位已经加注时，其当前投入会高于强制盲注。旧逻辑要求金额仍精确等于盲注，错误地报告“盲注尚未确认”。
5. 当 Hero 已经投入且单帧无法还原全部历史时，部分画面仍能通过三个递增投入层级和跟注按钮证明已经进入四次加注及以上。旧逻辑把这种明确的“不支持场景”混在“上下文不足”里。

## 修改

- 只截取完整客户端顶部约 3.5% 的标题栏并放大四倍后读取三盲结构；识别成功后继续沿用缓存。
- 三个水平对齐且大小接近的红色主按钮出现时，恢复完整的“弃牌/跟注/加注”集合；两按钮的“过牌/下注”面板不进入该规则。
- 允许同一按钮内被拆开的动作文字和金额重新合并。
- 强制盲注座位后续加注时，仍视为其盲注已经确认。
- 可见跟注金额超过命令行配置的有效筹码时，明确输出配置不匹配并等待，不再把错误筹码深度送入策略。
- 三个递增的非盲注投入层级、Hero 当前投入和跟注按钮金额相互闭合时，明确报告“当前策略不支持四次加注及以上”，但不伪造缺失的行动历史。
